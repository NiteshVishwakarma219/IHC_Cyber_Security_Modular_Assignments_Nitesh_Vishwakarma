The objective of this assignment is to study common web security vulnerabilities and their defenses in a controlled testing environment.

A web application follows a client-server model. A browser sends HTTP requests to a web server or application server, and the server returns HTTP responses. HTTPS is HTTP protected by TLS. TLS encrypts communication in transit and helps the client authenticate the server using certificates. HTTPS alone does not prevent application vulnerabilities such as SQL injection, XSS or CSRF.

SQL injection occurs when untrusted input is directly combined with an SQL query. A vulnerable query can allow an attacker to change the intended database operation. The demonstration should be performed only in an authorized training application such as OWASP Juice Shop. The main mitigation is to use parameterized queries or prepared statements instead of string concatenation. Input validation, database least privilege and safe error handling provide additional protection.

Reflected XSS occurs when untrusted input is returned in a web response and interpreted by the browser as executable content. The defense is context-appropriate output encoding and safe input handling. A Content Security Policy can provide additional defense in depth.

Stored XSS occurs when unsafe input is saved by the application and later displayed to users. Examples include unsafe comments or profile fields. Appropriate sanitization when HTML is intentionally allowed, context-aware output encoding, and Content Security Policy help reduce this risk.

CSRF occurs when an authenticated user's browser is induced to make an unwanted state-changing request. A common defense is an anti-CSRF token generated by the server and checked for every protected state-changing request. SameSite cookie settings, appropriate Origin/Referer checks, and re-authentication for sensitive actions can provide additional protection.

Web tracking can use cookies, third-party scripts, advertising pixels, browser storage and other identifiers. Privacy can be improved through data minimization, limiting third-party resources, appropriate cookie settings, clear consent and privacy information, reduced retention, and regular review of third-party services.

The practical testing approach is to use a deliberately vulnerable and authorized environment. For each vulnerability, normal behavior is observed first, a harmless test is performed, the result is documented, a mitigation is applied, and the test is repeated to verify that the vulnerability is addressed.

The main learning from this assignment is that web security requires multiple layers of defense. Secure coding, input validation, output encoding, parameterized database access, CSRF protection, secure cookies, HTTPS, monitoring and privacy controls work together to reduce risk.

The detailed report, safe annotated code examples, screenshots/illustrations, and presentation are provided as separate submission files.
